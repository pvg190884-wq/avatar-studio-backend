# Avatar Studio — локальное приложение для видео с собственным аватаром

Десктоп-приложение (Windows): создание аватара из фото/видео, клонирование
голоса, синхронизация губ с речью, сборка нескольких сегментов до 5 минут
каждый в один фильм с кроссфейдом. Вся генерация — локально на GPU
пользователя, без облака и без платы за генерацию.

## Что уже реально работает (проверено в этой сборке)

- Модуль склейки сегментов (`backend/pipeline/stitch.py`) — протестирован,
  ffmpeg xfade/acrossfade собирает несколько клипов в один файл с плавным
  переходом. Можно запускать прямо сейчас.
- Оркестратор FastAPI (`backend/main.py`) — эндпоинты для аватара, голоса,
  генерации сегмента, склейки проекта. Синтаксически корректен, поднимается
  локально.
- Electron-интерфейс (`frontend/`) — премиальный UI в теме монтажной
  студии: боковая рейка, три экрана (аватар/голос/монтаж), сигнатурный
  элемент — "плёнка" с сегментами и метражом. Синтаксис проверен.
- Полный поток UI → бэкенд: передача файлов с диска через IPC в main.js
  (fs.readFileSync + multipart), генерация каждого сегмента с опросом
  статуса задачи (`waitForJob` в `app.js`), финальная склейка через
  `/project/stitch`. Кнопка «Собрать фильм» сейчас честно покажет ошибку
  «липсинк-модель не подключена» — это ожидаемо, пока не сделан шаг ниже.

## Что нужно доделать вам (требует GPU, здесь недоступного)

Три места с `TODO(реальный инференс)` в коде — это ровно три модели,
которые нужно поставить на вашей машине:

| Модуль | Что делает | Модель | Требования |
|---|---|---|---|
| `pipeline/avatar.py::_build_face_embedding` | Идентичность лица | InsightFace (buffalo_l) | `pip install insightface`, веса ~350МБ, скачиваются автоматически |
| `pipeline/voice_clone.py::synthesize` | Клонирование голоса | Coqui XTTS-v2 | `pip install coqui-tts`, веса ~1.8ГБ |
| `pipeline/lipsync.py::generate_lipsync_segment` | Синхронизация губ | MuseTalk | git-клон `TMElyralab/MuseTalk`, веса ~5ГБ |

Код вокруг этих трёх точек — очередь, чанкинг по 20 сек для стабильности
лица, хранение профилей, склейка — уже написан и не потребует переделки,
когда вы подключите сами модели.

## Лицензии — проверить перед монетизацией

- **XTTS-v2**: Coqui Public Model License — некоммерческое использование
  свободно, коммерческое требует отдельного согласования. Coqui как
  компания закрылась в 2024, статус лицензии на сегодня стоит уточнить
  у форка `coqui-tts`, который её поддерживает, прежде чем продавать
  приложение или монетизировать его рекламой.
- **InsightFace**: некоммерческая исследовательская лицензия на веса
  buffalo_l — тоже требует проверки для коммерческого использования.
- **MuseTalk**: MIT-подобная, обычно свободна для коммерции — но
  перепроверьте актуальную лицензию репозитория перед стартом.

Это единственный реальный барьер на пути к продаже приложения — не
технический, а юридический.

## Установка (после того как подключите модели)

```bash
# Бэкенд
cd backend
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu121
pip install insightface coqui-tts
git clone https://github.com/TMElyralab/MuseTalk
uvicorn main:app --port 8420

# Фронтенд (в отдельном терминале)
cd frontend
npm install
npm start
```

## Упаковка в .exe для конечных пользователей

Сейчас `main.js` запускает бэкенд как `python -m uvicorn` — это требует
Python на машине пользователя, что для обычного человека не вариант.
Перед публикацией:

Файловый IPC уже реализован (main.js читает файл и отправляет multipart
сам, renderer никогда не видит fs) — ничего доделывать здесь не нужно.

1. Упаковать `backend/` через **PyInstaller** в один исполняемый файл
   (веса моделей — отдельно, скачивать при первом запуске с прогресс-баром,
   не вшивать 7+ ГБ в установщик).
2. В `main.js` заменить `spawn('python', ...)` на путь к собранному exe.
3. Собрать установщик: `npm run build:win` (electron-builder уже в
   `package.json`).

## Честная оценка объёма работ

То, что в этом проекте — рабочий каркас и премиальный интерфейс, а не
готовый продукт. Реалистичные шаги до первого работающего прототипа
на вашей машине:

1. Поставить три модели и подключить их в трёх TODO-точках — по опыту
   аналогичных пайплайнов, это несколько дней на человека с опытом Python/ML,
   в основном борьба с версиями CUDA/torch.
2. Прогнать первый сквозной тест: фото → аватар → голос → 30-секундный
   сегмент — и посмотреть на реальное качество липсинка на вашем GPU.
3. По результатам — решить, устраивает ли качество MuseTalk, или нужен
   Hallo3/SadTalker как альтернатива (компромисс качество/скорость/VRAM
   у каждой модели свой).
4. Только после этого имеет смысл вкладываться в упаковку под конечного
   пользователя (PyInstaller, установщик) — раньше это трата времени,
   если качество генерации не устроит на шаге 2.
